# 文章内容（第一期）

- 唯一分类为 `faq`（常见问题），保存时必选。正文使用公共富文本编辑器，支持登记上传的图片或 HTTPS 图片。
- 管理入口为 `#articles`，旧 `#faq` 入口重定向到此处。前台为“我的 → 常见问题”。
- 文章范围为全站 `all` 或多个指定考试 `exams`；全站与考试列表互斥，指定考试至少一项。
- 列表及前台均按 `created_at DESC, id DESC` 排序，编辑、上架下架不修改创建时间。标题仅截断展示，不截断保存的原文。
- `GET /api/admin/articles` 支持标题、考试项目、状态及每页 20 条分页；PUT 保存、PATCH `/:id/status` 上下架、DELETE 删除均要求原版本，防止覆盖并发修改。
- `GET /api/faqs/:examId` 及 `/api/catalog/:examId` 的 `faqs` 使用同一范围过滤和排序，仅返回已上架、未删除文章的公开字段。

## 数据兼容

沿用 `other_content` 的 `kind='faq'` 行、原内容 ID 和入库号。分类、范围、考试 ID 列表、创建人 ID 与姓名快照保存在 `payload.article`，正文仍在 `payload.document/content`。无需修改既有表结构。

创建人由服务端取登录管理员，客户端不能指定。已有文章未记录创建人的，显示“未记录”，后续编辑不会把编辑人误记成创建人。旧文章没有 `payload.article` 时，原 `exam_id` 为空表示全站，否则表示原单个考试；编辑后以新范围为准，保留原数据库身份字段。

删除使用 `payload.deletedAt` 并下架，保留审计和身份记录；页面不提供恢复。旧通用保存接口拒绝 FAQ 写入，避免绕过分类、范围和创建人校验。

图片沿用现有内容资源索引，保存及删除与资源清理共用引用锁；下架文章仍保护图片，删除后不再占用资源引用。资源管理定位 FAQ 时打开文章编辑抽屉。

验证：`tests/articles.test.ts`（范围、排序、并发、权限、兼容与资源保护）、`tests/articles.browser.mjs`（后台实际操作、用户端展示、四级标题单行省略）。全部测试使用临时数据库，不修改本地业务数据。
