# 数据字典与中文操作日志

系统管理 → 数据字典提供结构查询；系统管理 → 操作日志提供后台操作检索。两者只向超级管理员开放。

## 数据字典

`GET /api/admin/data-dictionary` 从 PostgreSQL / PGlite 的系统目录读取 `public`、`migration_archive` 中的数据表和视图。展示字段类型、可空性、默认值、主键、联合唯一约束、外键、检查约束和索引，不读取业务记录，不接受 SQL 或任意表名参数，不提供修改和删除操作。

`apps/api/src/data-dictionary-notes.ts` 维护中文表用途、字段含义和 JSON 内容说明。数据库结构始终实时读取；新增迁移后未写说明的表或字段显示“待补充说明”，不会猜测含义。增加表或字段时应同步维护说明，特别是 JSON 字段、状态值、金额单位和考试归属。

当前结构包含 61 张表（含 3 张迁移归档表）、3 个兼容视图、520 个字段。`content`、`exams`、`course_links` 是兼容视图；页面明确区分实际表、视图和迁移归档。关联关系仅展示真实外键，应用代码维护的关系和 JSON 内的资源标识在业务说明中说明，不冒充数据库约束。

## 操作日志

- `GET /api/admin/audit/options`：实际已有操作的中文选项。
- `GET /api/admin/audit/records`：按操作代码、操作人姓名或手机号、对象标识、起止时间检索；每页 20、50、100 条，按时间及标识稳定倒序。
- `GET /api/admin/audit/records/:id`：只读详情，敏感凭据字段递归隐藏。
- 原 `/api/admin/audit` 保留原数组返回形式，以兼容现有调用。

操作中文名称统一维护在 `apps/shared/audit.ts`，覆盖操作日志页、工作台最近操作、用户详情中的账号/权益/订单历史、订单管理的处理记录。新增操作必须补充词典；商品历史恢复支持动态版本号，未知历史代码显示“其他历史操作”。数据库中的稳定操作代码及原始历史记录不被改写。

日志详情使用中文项目名称和常见状态说明；模型名、记录标识、文件名等原始业务值保持原意。用户行为选项卡沿用未开发占位，本次没有新增前端行为采集。
