## 当前网络的验收限制

本轮检查时 Windows 代理已启用，供应商域名均被解析到 `198.18.x.x` Fake-IP 地址。因此，即使请求使用独立 HTTPS agent、不读取应用层代理，也不能绕过 VPN 对 DNS 或系统路由的接管。诊断输出明确标记 `INCONCLUSIVE_FAKE_IP`，不会把 HTTP 可达称为无 VPN 可达。

AI 接口仍保留内网/保留地址拦截。后续修复增加了仅针对域名全部解析为 Fake-IP 的直接 DNS 查询回退，所有回退结果必须重新通过公网地址校验并固定用于连接，TLS 校验不变；解析失败、私网或混合结果仍阻止请求。本机修复后真实模型工具调用和 AI员工读取题库页面均已通过，但系统代理仍开启，不作为无 VPN 直连验收。不要通过允许所有保留地址、关闭 TLS 校验或把 API Key 交给浏览器解决；最终仍需在无 VPN 的部署环境中验证。

短信、微信、支付宝本轮仅查询公开端点的网络响应，没有发送短信、创建交易或调用真实登录流程。HTTP 400/401/404 可说明收到了服务端响应，不能证明凭据或业务配置有效。

## 重复检查

启动本地服务、配置本地管理员环境变量后运行：

```powershell
node scripts/check-direct-network.mjs
```

脚本通过 API 检查已有配置和数据、登录后台浏览页面、生成验证码预览、读取已启用 AI 服务的模型列表。不会修改业务内容、发送短信、创建订单或调用收费文本生成；会产生正常登录/模型读取审计、临时验证码和媒体预览凭证，并注销自己的管理员会话。输出不包含密钥、正文、用户手机号或资源签名地址。

`browserStatus: PASS` 仅表示本次覆盖页面不需要浏览器外网依赖。`externalNetworkStatus` 单独报告第三方接口，必须结合部署机器的路由环境判断；未检出 Fake-IP 也不自动证明无系统级代理。

## 发布要求

1. 在中国大陆、未安装 VPN 的正式部署网络测试页面、资源播放下载、AI模型读取和真实业务流程；供应商故障不应阻塞普通内容页面。
2. AI 仅配置部署服务器可直接访问的服务。若现有服务无法稳定直连，改用已完成直连验证的国内服务商，并重新测试模型能力；不要自动替换已有密钥或模型。
3. 前端依赖继续本地打包，不新增海外运行时脚本、字体、图标 CDN。用户上传内容继续使用登记资源管线。
4. 首次安装的 npm / GitHub 下载与网站运行分开。部署已构建静态文件、服务端依赖和已校验的 GoCaptcha 发行包，运行时不执行下载安装。现有 Windows 安装脚本支持预先放置 `.local/go-captcha/service.tar.gz`，核验固定 SHA256 后本地解压，无需再次访问 GitHub；发行包版本和摘要见 `INTEGRATIONS.md`。
