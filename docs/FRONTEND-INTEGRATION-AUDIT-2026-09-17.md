# 前后端衔接检查 · 2026-09-17

本轮是检查，不修改业务实现。主要流程已有真实接口，当前更需要统一考试范围、个人状态、失败恢复和旧界面文案。

## 检查范围与方法

- 代码梳理：学生端全部 26 个注册页面、服务层、个人缓存、对应 API；后台导航及列表、消息、推荐码、权限等相关实现。
- 浏览器：学生端 393px 视口遍历 26 个页面入口及个人中心 7 个模式；后台 1440px 视口遍历 27 个入口。预览、支付、小抄详情、学习报告等无有效参数的入口只检查落地表现，不代表完整业务验收。
- 浏览器业务与故障场景使用独立临时数据库和测试会话。消息场景模拟站内消息返回数据，后续按钮实际调用隔离 API。故障注入只在测试浏览器中生效。
- 现有 PostgreSQL 服务只读取公开的考试、目录、系统设置、商品和搜索接口，6 项均返回 200；没有修改现有业务数据、支付、发送消息或调用收费 AI。
- 学生端 `npm run type-check --prefix apps/user` 通过。普通入口遍历未捕获页面 JavaScript 异常或页面级横向溢出；不代表没有下述业务问题。
- 使用 `ui-ux-pro-max` 技能的加载、错误反馈、防重复提交检查规范，指导故障场景检查，没有改动设计系统。
- 微信小程序未做真机运行，微信/支付宝未做真实交易。本轮不重新设计学习计划、掌握程度、薄弱项、AI复习资料、学习报告或背题规则。

可重复检查脚本和结果在 `.local/qa/frontend-audit.mjs`、`.local/qa/admin-integration-audit.mjs`、`.local/qa/frontend-focused-audit.mjs` 与 `.local/qa/frontend-audit/` 中；这些本机 QA 文件不提交仓库。

## 优先修复：业务结果不一致

### 1. 切换考试失败后，新考试名称与旧考试内容混在一起

**已浏览器复现。** 切换至中级考试时让目录请求失败，本地当前考试已经变成 `mid-social-worker`，知识图谱仍显示初级专属内容。

原因：`apps/user/src/store/app.ts` 的 `selectExam` 先写当前考试并清个人缓存，再依次拉目录、权益、记录；中途失败没有回滚，也没有统一的切换中状态。`clearPersonalCache` 不重置权益对象和目录。

建议：先加载目标考试必要数据，成功后一次性切换；失败保留原考试。请求需绑定账号、考试和切换批次，避免旧结果覆盖新状态。

### 2. 推荐码设定的赠送时长没有用于实际履约

**已隔离接口验证。** 配置赠送 VIP 24 小时，使用接口返回成功及 24 小时，但实际写入人工权益时直接选结束日期最晚的考期，没有使用 `permission_hours` 计算截止时间。在包含未来考期的样例中，关联到了未来考期，整个考期跨度 8760 小时，而非 24 小时；当前权益仍来自原订单。

证据：`apps/api/src/routes.ts` 的 `/referrals/use`、`apps/api/src/membership.ts` 的 `manualEffective`；学生端 `pages/profile/index.vue` 直接展示接口返回的“获得 N 小时”。

建议：明确推荐码赠送的当前有效考期和截止时间，履约统一为独立赠送记录；不能把限时赠送写成整考期人工覆盖权益。成功提示和“我的权益”使用实际发放结果。登录扫码自动使用推荐码时的失败也应提示，而不是空 `catch`。

### 3. 消息中心“全部已读”调用旧公告接口

**已浏览器复现。** 展示站内消息后点击全部已读，实际发出 `PUT /records/:examId`，把消息 ID 当作旧内容公告 ID；确认弹层仍停留，没有完成已读。

单条展开已改用 `/messages/:deliveryId/read`，批量操作尚未同步。后台已有 `/messages/read-all`，但它会标记账号所有考试的消息，不能直接替换后就认为满足当前考试范围。

建议：按当前考试或显式消息投递 ID 批量标记，统一未读数量与红点。首页和“我的”目前还根据本地布尔值决定红点，单条阅读、新到消息与跨端状态不可靠。

证据：`apps/user/src/pages/profile-center/index.vue` 的 `toggle`、`confirmMarkAllRead`；`pages/index/index.vue` 的 `hasUnreadMessages`；`apps/api/src/routes.ts` 的消息接口。

### 4. 停用考试后，目录接口仍返回其已发布内容

**已隔离接口复现。** 将考试停用后，`GET /catalog/:examId` 仍返回 200 和该考试的科目、题目。考试列表虽然隐藏了该考试，持有旧选择缓存的学生仍可能进入旧内容。

原因：`apps/api/src/content.ts` 的 `catalog` 只检查内容和祖先发布状态；`publishedContent` 同样未统一校验所属考试启用状态。

建议：统一学生内容可见性校验；当前考试失效时引导选择其他考试，不能只在考试选择列表隐藏。

## 文案、性能和后台操作体验

1. **错题本旧文案冲突。** 空态仍写“重新答对后自动移出”，清空确认仍写“恢复为未做状态”。实际答对保留错题，清空也保留答题历史，符合此前要求；只需改提示，不能倒改正确的后端规则。位置：`pages/practice-tools/index.vue`。
2. **跨考试名称写死。** 错题、笔记的科目标签会把非实务统一显示成“初级综合”，部分详情按是否包含“实务”来生成初级名称。改用服务端返回的实际考试、科目路径。位置：`pages/practice-tools/index.vue:subjectShortName`、`pages/note-detail/index.vue:source`。
3. **重复请求和整包目录依赖。** 隔离环境一次已登录首页进入记录到 20 个 API 请求，权益/平台设置/学习计划各请求 3 次；`App.onLaunch` 和页面 `onShow` 重复加载，初始化结束又 reLaunch。现有初级目录公开接口返回约 307 KiB 未压缩 JSON，搜索打开一条结果、进入课程还重新加载整包目录。建议统一启动状态、同请求合并、按考试缓存目录版本，详情单独取数；随题量扩大再按需分页。
4. **保存按钮防重复与失败重试。** 学生端已有全局错误处理器，实测笔记保存失败会提示且不会假报成功，不能认定“全部静默”。但笔记保存、收藏和批量操作缺少统一 busy 状态，部分操作只给瞬时 Toast。建议禁用重复点击、保留输入、提供局部持续错误；批量部分成功时同步剩余项。位置：`apps/user/src/main.ts`、`utils/notes.ts`、`utils/favorites.ts`。
5. **后台消息操作吞掉失败。** `apps/admin/src/MessageManagement.vue:remove/sendRow` 把取消弹窗与接口失败都放在空 `catch`；保存模板和消息草稿也缺少统一提交锁。建议只忽略用户取消，接口错误明确展示，发送中禁止重复提交。
6. **分页有“只显示前一部分”的情况。** 用户管理接口最多 200 条；后台消息列表最多 200 条再本地分页；学生学习历史最多 100 条；学生消息最多 200 条。当前无溢出不代表历史完整。建议返回 `items/total/page`，服务端筛选分页，前端明确可继续加载。不能以当前返回条数作为真实总量。
7. **调试入口仍直接展示。** 首页、课程、刷题、我的等仍有“调”按钮，没有构建环境开关。它目前不能授予服务端会员，但会干扰正式展示。建议仅开发环境可见。

## 小程序与真实支付：单列待验收

- `StudyContent.vue:membership()` 直接访问浏览器 `location.hash`，未包裹 H5 条件；小程序点击受限资源后的登录/权益跳转需要改成跨端取路由方式。
- 图片与音视频常直接绑定后端返回的 `/api/...` 相对地址；讲义下载已做部分绝对地址转换，其他媒体需统一。小程序合法域名、HTTPS、授权过期后重取地址需要真机验证。
- 支付渠道与回调实现已有，不可将“未做真实支付验收”写成“没有支付接口”。当前未使用真实商户凭据；仍需验证支付应用返回、取消后恢复、回调延迟、刷新查单。支付页当前主要依靠手动“我已支付，查询结果”，可以增加前台恢复后的限频查询。
- 学习时长与掌握算法按此前约定继续讨论，本轮不新增采集或修改规则。

## 建议实施顺序

第一批：考试切换一致性、推荐码限时履约、考试停用校验、消息全部已读。

第二批：课程进度与续播、订单考试范围、下架内容个人记录、登录失效和错误页面、主观题提交统计。

第三批：文案与真实路径、请求合并和目录缓存、分页、操作防重复、小程序适配与真机验收。

这轮不需要大改视觉风格。先让“当前考试、当前账号、操作结果、学习进度”在前后台保持一致，再统一加载、空态和错误组件。
