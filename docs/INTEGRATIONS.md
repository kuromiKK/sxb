# 验证码与短信接口

系统设置 → 接口配置内分别配置「验证码」「短信」，保存后立即生效。微信登录、微信支付仍为等待开发。修改需要管理员会话，配置有并发版本校验和操作日志。

## GoCaptcha

- 后台登录始终使用 GoCaptcha 服务端验证。填写手机号和密码后点击登录，弹窗验证成功才提交登录；采用当前配置的验证方式、提示语和配色。此场景不受用户端「前端生成」或短信/讲义开关影响。
- 登录验证使用独立的 `admin-login` 场景，凭据绑定管理员手机号及请求 IP，单次使用、两分钟过期；错误密码也会消耗凭据。服务不可用时阻止登录，不降级绕过验证。后台登录页 Logo 读取已发布的基本设置，保持原 38×38 尺寸。
- 调用 `/auth/admin` 的维护脚本现在也必须提供验证通过的 `captchaProof`，旧的仅手机号和密码调用会被拒绝；不存在测试环境免验证的登录后门。

- 当前开放官方服务内置的 **滑动拼图、拖拽拼图、旋转拼图、中文点选、英文点选、图形点选**；中文和英文点选分别支持普通/深色提示图，共八个选项。后台支持开关、发送短信/讲义下载场景、提示文字、60～300 秒有效期，以及未保存配置的真实服务预览。
- 外观独立配置：浅色/深色面板，蓝、紫、绿、橙、红、青六种预设配色，以及任意 HEX 自定义颜色。按钮、滑块、点选编号和加载状态使用统一配色，按钮文字根据背景亮度选择深浅色。切换方式自动更新默认提示，自定义提示保留；更改配置会清空旧预览，重新生成后才能验证。
- 后台使用 `go-captcha-vue`，学生端使用 `go-captcha-uni`（H5、微信小程序构建）。前端只收到随机挑战 ID 和拼图图片，答案与上游缓存键不下发。预览不产生可用于业务的凭据。
- 每个挑战只允许一次验证；失败需刷新。成功凭据两分钟内、单次使用，绑定手机号，或学习会话和具体讲义。真实短信必须开启 GoCaptcha 的短信场景。服务异常不会退回前端验证码。
- 验证方式随挑战存入数据库；提交时由服务端按该挑战的类型校验坐标、点选顺序或旋转角度，不能用请求参数切换校验器。配置改变不影响已签发挑战的类型。手机缩放只换算坐标，不缩放角度；旋转图片不会把目标角度传给前端。
- 「前端生成」仅是简单操作确认，没有服务端防机器人能力，仅适用于本地测试/非敏感操作。
- GoCaptcha 开源免费，但图像生成与核验由自己的独立服务承担，不是免费托管服务。大规模防短信轰炸仍需网关限流、监控和阿里云控制台额度。

### 本地启动

Windows x64 首次运行 `node scripts/setup-go-captcha.mjs`，再运行 `node scripts/start-local.mjs`。启动脚本现在包含验证码服务，其他已运行服务不会重复启动。

安装脚本固定官方 `wenlng/go-captcha-service` v1.0.5 Release 下名为 `go-captcha-service-1.0.6-windows-amd64.tar.gz` 的资源（上游版本名称不一致），并校验 SHA256 `33181f89353f537e465dc9e34d2f6618f0fc39f97544d7bb2fae09383f80d054`。二进制、配置与缓存均在忽略提交的 `.local/go-captcha/` 内。保留开源发行包和许可证说明。

HTTP 仅监听 `127.0.0.1:4311`；gRPC 仅监听 `127.0.0.1:54311`。管理接口使用独立随机密钥，保存在本地服务配置，切勿下发前端。仅平台 API 代理挑战和校验，没有管理接口代理。

其他系统使用官方对应系统发行包/容器，将 `GOCAPTCHA_URL` 指向私网服务，并根据部署设置 `GOCAPTCHA_API_KEY`。**禁止公开 GoCaptcha 的管理接口或端口**，其中的状态接口包含正确答案。无管理操作需求时配置精确管理路由的 `auth_apis` 且 `api_keys: []`，上游会全部拒绝。不能用 `/api/v1/manage` 前缀代替逐个路由，上游按完整路径匹配。

生产 API 设置 `APP_MODE=production` 和稳定的 `SECRET_KEY`，使用 HTTPS；微信小程序需设置实际 HTTPS API 地址 `VITE_API_BASE` 并配置请求/下载合法域名，不能用本机环回地址。当前已完成编译兼容检查，发布前还需微信开发者工具和真机联调。多实例服务需共享上游 Redis 缓存，平台 API 需共享 PostgreSQL；网关按可信客户端 IP 限流，不能直接信任任意 X-Forwarded-For。

## 阿里云短信

基于阿里云官方 `@alicloud/dysmsapi20170525` SDK，调用 `SendSms`（2017-05-25），端点 `dysmsapi.aliyuncs.com`。本期仅中国大陆手机号的登录验证码。

后台配置：

1. 选择关闭 / 本地测试 / 阿里云真实短信。
2. 填写 RAM 用户 AccessKey ID 与 Secret（需要 `dysms:SendSms`）。两者同时更新，留空保留已有值，支持明确清除。服务端 AES-256-GCM 加密保存，不回显。
3. 填写已审核短信签名、`SMS_` 开头的验证码模板编号、验证码变量名（默认 `code`）。本期模板应只包含此验证码变量，不支持额外动态参数；控制台模板正文中的有效期需与后台配置保持一致。
4. 设置 4/6 位数字、300～600 秒有效期、60～300 秒重发间隔、每手机号每日 1～30 次（北京时间自然日）。每 IP 额外限制 30 次/小时，失败请求也占用发送额度，防止不断重试。

验证码使用安全随机数，数据库只保存哈希，5 次错误即失效，验证成功即消费。预留发送记录与限流检查在事务内串行执行；避免并发重复发送。请求超时不自动重试，以免重复计费。发送参数不含密码、完整密钥或验证码日志。

真实模式不返回验证码；本地测试模式不请求阿里云，会返回测试码。生产环境禁止测试模式。当前没有配置真实凭据，不进行任何收费测试发送。

后台显示最近 30 次脱敏发送记录。`accepted` 表示阿里云 `Code=OK` 已受理，不代表已送达；本期未接送达回执。失败记录保留供应商错误码和 RequestId，便于对照阿里云控制台排查。网络超时可能已受理但响应未返回，应等待重发间隔，不立即重试。

## 验证

- `node --experimental-strip-types --test tests/integrations.test.ts`：独立测试库和模拟供应商，验证绑定、防重放、过期、并发、加密、无明文泄露、发送失败、登录、频率与每日上限。
- `node --experimental-strip-types tests/integrations.browser.mjs`：独立测试库、实际本地 GoCaptcha，验证后台预览和 H5 拖动、失败刷新、短信测试流程。测试仅在服务端读取本地管理密钥以获得自动化测试的拼图位置，不在生产代码中提供解题接口。
- `node --experimental-strip-types tests/captcha-variants.browser.mjs`：独立测试库、实际 GoCaptcha，逐项验证八个选项的后台预览与学生端交互、保存后的生效、深浅主题和窄屏布局。
- 数据库迁移 23 建立接口设置；迁移 24 为挑战增加验证方式快照，并为旧配置补充滑动拼图/浅色面板默认值。不清空用户、订单或原有配置。
