# Learning data, phase one

The admin `#records` page provides six read-only tabs: overview, visits, answer attempts, wrong notebook, favorites, and notes. Existing `/admin` superadmin/session guards apply. User phone numbers in responses are masked; an admin may search by nickname or phone.

## Definitions

- A visit begins after a logged-in user successfully loads a published knowledge/recitation page or an authorized course page. Browsing a catalog, opening a product, failed loads, and locked courses are not visits. The capture endpoint also accepts published subject/chapter/section content for future readers; their directory navigation does not emit visits.
- A visit is identified by user + client session ID. Retries and page refresh reuse the same ID. Leaving a page ends its client session; reentering starts another. Startup catalog initialization must complete before capture, to avoid counting the app's initial route relaunch twice.
- The server stores content title/type/path snapshots, start time, last confirmed activity, and optionally the latest media position. It does not claim completion, mastery, elapsed study time, or an inferred end time.
- Playback progress updates only while the position changes, at most every 45 seconds during playback, with an extra flush attempt on pause/end/leave. Server updates are limited to once in 10 seconds and protected by an increasing sequence. Rapid final updates or browser termination can leave the last position slightly behind. No interval heartbeat or per-operation playback history is stored. Existing per-course progress is updated in place.
- Knowledge text media blocks do not emit their own progress stream in this phase; their parent knowledge content still has its visit. Structured courses report video/audio progress.
- Overview metrics: distinct visiting users, visit count, distinct submitting users, and question submission count. A configured question submission (including a subjective answer waiting for grading) counts once; its generated legacy answers row is excluded. Grading changes never add submissions. Repeated valid attempts count again. A composite question is one question, not one per subfield.
- Days use Asia/Shanghai. A selected range is inclusive of its final calendar day. Unique people across a range are computed from per-user/day/exam rows, never by adding daily people counts. Queries allow at most 366 days. Records filter by visit start time.

## Storage and cost

Migration 20 adds `learning_visits` and `learning_daily_users`. Inserts atomically increment daily per-user counters using DB triggers; overview queries use those counters instead of scanning the entire visit/answer history. Visit lists have date/exam/user indexes and server pagination (20/page). Capture preserves a single legacy learning event per newly inserted visit for existing monthly reports/history, with zero inferred minutes.

Existing question submissions are summarized during migration, excluding duplicate legacy rows. Old content visits are not reconstructed from favorites, notes, progress, or older learning events. The overview shows the collection start timestamp. Tests, imports, or future deletion tooling that directly modifies submitted answers must also maintain/rebuild the daily summaries; normal product APIs do not edit or delete past submissions.

New collection is limited to two lightweight endpoints: `POST /learning-visits`, `PUT /learning-visits/:id/progress`. Credentials, owner checks, publication state, course entitlement, schema limits, and request sequencing are validated server-side. A failed telemetry request does not block reading or playback. All new automated/browser fixtures use isolated databases, never live student records.

## Answer records and personal collections

`GET /admin/learning-data/collections/:kind` and `/:id` support `answers`, `wrong`, `favorites`, and `notes`. Lists are paginated (20/page); filter defaults include all dates, users and exams. Time ranges use inclusive Shanghai calendar dates. Answer dates mean submission time, wrong notebook dates mean last incorrect attempt, favorites mean creation time, notes mean last database update. Title, question type/result, content kind and note text filters apply to relevant tabs. No admin write/delete routes are introduced.

- Answers combine `question_submissions` and legacy `answers`; matching user/request IDs exclude the objective mirror row. AI pending/processing/failed and self-review/self-graded results retain their actual status; ungraded subjective work is never reported as an incorrect objective answer. Scores are never inferred for legacy records. Field-level answers, reference answers, scoring criteria and feedback are viewable read-only.
- Migration 21 adds nullable legacy question snapshots and query indexes. Newly submitted questions retain title/payload/version at submission; existing configured snapshots remain intact. Old missing snapshots are explicitly labeled and fall back to current content for reference only. Historical answer references/feedback remain unchanged. Snapshot media references participate in resource cleanup protection and link back to the answer drawer. Configured submissions also receive entry numbers under the existing identifier convention.
- Wrong notebook membership is based on the most recent **incorrect** objective submission being later than the user's dismissal, not on the most recent answer being incorrect. Correct attempts keep the item. Explicit clearing removes all retained wrong items, even those subsequently answered correctly; a later incorrect attempt re-adds it. Counts are lifetime incorrect attempts for that user/exam/question, independent of date filters or past clearing. Detail history displays the latest 20 attempts; full history is in the answer tab. Frontend storage and server stats use the same rule. Subjective scoring alone does not create a wrong item.
- Favorites/notes reflect current saved user records, not a click log. User edits update a note in place; removal makes it disappear from admin lists. Notes preserve plain text/newlines and can belong to questions, knowledge points and courses (premium and existing companion-course records remain compatible). References are resolved against actual content instead of trusting client-supplied type labels. Missing/disabled content does not hide the personal record. No fabricated note history or historical visits.
- AI revision materials and learning reports are outside this phase. This extension does not add continuous client telemetry.
