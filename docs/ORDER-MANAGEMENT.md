# 订单管理（第一期）

- 商品与订单内容以创建订单时的商品快照为准。详情包含商品版本、价格、图文、考试、考期与权益档位。
- 列表按商品、类型、考试、考期、状态、用户/订单号、创建/支付日期筛选；权益档位和考期不作为列表列，仅显示在详情。日期按北京时间解释，服务端分页。
- 支付失败属于可重试的支付尝试；原订单仍为待支付，超过有效期后关闭。每次尝试保留独立支付流水。
- 支付成功记录实际权益生效/到期时间、体验时长与短时确认事实。商品后续变更不重写订单或已发放权益。

## 人工退款

只支持全额线下退款登记，不调用任何真实退款接口。

1. 已支付 → 待线下退款：工作人员登记原因并联系用户，权益暂时保留。
2. 待线下退款 → 已退款：工作人员实际完成线下退款后，填写退款凭证或转账流水号并确认；系统撤销该订单发放的权益。

状态修改在事务内校验当前状态，重复/过期请求拒绝；记录操作人、时间、原因、凭证和金额。人工配置和其他订单权益不受影响。

## 测试订单删除

只在非生产环境提供，并要求订单明确为测试数据且没有真实支付记录。输入完整订单号和原因后二次确认。

删除后从后台及用户端订单列表移除，撤销该订单权益，禁止继续支付。数据库保留软删除底稿、支付记录及操作审计；历史已支付事实仍参与“终身体验一次”等资格判断。生产环境、正式订单和真实支付记录均禁止删除。
