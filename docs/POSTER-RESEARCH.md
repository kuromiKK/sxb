# 海报生成开源方案调研

核对时间：2026-09-16。范围：后台推荐码套模板、未来小程序分享图和学习报告海报。本次仅调研，未接入海报功能。

## 建议

第一期用固定模板与变量替换，不引入完整在线设计工具。管理员选模板，系统填入推荐码二维码、考试名、宣传文字和品牌图；前端以后复用相同模板服务。建议采用 `@napi-rs/canvas` 服务端生成，结果缓存，同一模板版本和数据不重复渲染。小程序只获取并保存生成的图片，可保持网页和小程序视觉一致。

如果以后要求在小程序本地离线绘制，可以评估 Painter；如果要求运营人员自由拖拽制作模板，再考虑完整设计器。

## 对本项目的具体约束

- 普通二维码可由现有 `qrcode` 生成；微信小程序码需要微信官方小程序码接口与 AppID，绘图库不能凭空生成有效小程序码。
- 推荐码海报与报告海报共用“模板版本 + 场景 + 数据”协议；学习报告图片必须明确属于哪个用户、哪个考试，分享时仅包含用户选择公开的信息。
- 中文字体随服务部署，明确授权，不依赖访问境外字体 CDN。测试超长中文、英文数字混排、表情和不同字号。
- 背景、Logo、上传素材以及需要长期保留的生成海报纳入已有资源管理，保留引用；课程私有附件不能通过海报接口公开。
- 生成端限制画布像素、图片尺寸和并发；缓存输出，不在每次打开二维码时重复绘制。不要允许模板任意访问内网 URL 或执行脚本。
- 小程序自定义字体、下载域名、相册保存权限以及真机效果需单独验证。海报图片和“小程序分享卡片”是两种输出，需要分别适配比例。

第一期建议只提供 3～5 个设计好的模板、预览与下载，不上自由拖拽编辑器。
