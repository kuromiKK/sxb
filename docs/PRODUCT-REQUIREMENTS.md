# 商品管理

## 已确认范围

- 交易管理下依次为：商品管理、订单管理、财务管理。
- 商品基础模型可扩展；第一期仅支持正式权益商品、体验权益商品，不要求未来其他商品类型关联权益。
- 两种权益商品均必须关联考试、考期、该考试的权益档位，权限仍由会员权益集中配置。
- 名称分为前端商品名称（`frontend_title` / `frontendTitle`）与后台商品名称（原 `title`）。基本信息先显示前端名称，商品概览、用户端商品和订单使用前端名称，后台商品及订单管理使用后台名称。两项独立保存，旧商品以前一个名称回填前端名称。
- 考期必须配置开始时间、结束时间（北京时间）；不支持按天正式套餐、不预售，考期结束后停止售卖。
- 同一商品售价不随考期剩余天数自动折算；正式权益在支付后生效，到考期结束失效。VIP/SVIP到期恢复普通会员，不向下一考期延续。
- 正式权益同一账号、考试、考期只允许购买一次；不能通过另建同类商品绕过。体验单独计次，不阻止之后购买正式权益。
- 所有购买先创建待支付订单，支付成功后发放权益。失败/取消订单不占体验次数；已支付记录永久保留，改价不修改历史订单。

## 体验规则

- 一个账号终身只能体验一次，跨考试、跨考期、跨体验商品均不重置。
- 曾经购买正式权益的账号也不能再体验，不能只检查当前是否会员。
- 体验复用指定档位的权益，支付成功立即开始，最晚在绑定考期结束时失效。
- 创建/编辑体验商品必须填写：体验时长、最低可购买剩余时长、剩余时长不足的支付确认提示语。
- 时长必须大于零，最低可购买剩余时长不得大于体验时长。
- 支付前按服务器时间复核：剩余时长 >= 体验时长正常购买；最低时长 <= 剩余时长 < 体验时长提示确认；剩余时长 < 最低时长禁止支付并说明原因。
- 例：体验36小时、最低10小时。剩余36小时正常购买；剩余10～不足36小时，弹窗提示实际可用时长与考期结束时间；不足10小时禁止购买。
- 提示语需支持实际可用时长、体验时长、考期结束时间变量，不能仅靠任意静态文字隐藏实际时长。
- 待支付订单也必须再次校验，用户早先确认不代表之后仍符合购买条件。

## 版本与订单

- 每次保存、上下架均追加不可修改的历史版本；恢复历史版本会生成新版本，保留完整历史。
- 已售商品的类型、考试、考期、权益档位不可修改，恢复历史版本也遵守此限制。
- 订单保存创建时的商品版本、价格、内容与权益配置快照，商品后续改价不影响原订单。
- 新版本和订单快照同时保存两个名称；旧历史版本与订单不重写，缺少前端名称时使用其原名称，恢复旧版本也遵循该规则。
- 支付时再次验证商品是否可售、考期、购买资格及体验剩余时长。下架后待支付订单不能继续付款，已支付权益不受下架影响。
- 已发放权益记录固定到期时间，修改商品不会改动既有权益；正式权益购买成功后结束同考试的体验权益。
- 有订单的商品不能删除；历史版本中的图片保留资源引用，避免清理后无法恢复。

## 已实现范围与支付边界

后台商品列表、筛选、编辑、上下架、历史版本查看与恢复，前端商品列表、详情、下单、短时体验确认与权益发放已接入同一套商品配置。

商品基础表、权益配置表、历史版本表分离，为其他商品类型预留扩展；第一期仅支持正式权益和体验权益。会员权限继续由会员权益集中控制。

当前支付沿用测试支付，不产生真实扣款；生产环境禁用模拟支付。真实支付渠道及其回调尚未接入。测试订单未作批量删除。
