## 1. 考前小抄

已确认：

- 每个考试支持多篇小抄，每篇为一篇图文，可附带讲义下载。
- 内容重要，可能属于合法但需要限制传播的内部资料；仅在考前提供给 SVIP 用户。
- 后台必须有独立的“考前小抄”模块，可编辑内容、指定所属考试及使用周期。
- 每篇设置开放时间与截止时间，后台可以提前开放或延期。
- 未开放显示开放日期；非 SVIP 可看到标题与简介，正文提示 SVIP 专享；过期后保留列表记录但不能阅读。
- 后台上传的讲义允许有权限的用户下载，正文不提供下载或导出，其他内容不提供下载。
- 到开放时间通过学习计划提醒，在首页学习计划下面出现入口。用户还希望在刷题金刚区有入口，但位置与交互尚未确定。

- 用户已确认：开放时仍显示一次资料开放通知，不受当天休息或关闭小抄复习提醒影响；后续复习提醒遵循用户的计划设置。“一次”需按用户及资料记录送达/展示状态，不等同于关闭 H5 后能收到系统推送。

待讨论：刷题金刚区的具体位置。小抄内容及讲义下载均需校验对应考试的 SVIP 权益和开放时间；不把入口隐藏当作权限控制。

之前建议的“我的”固定入口、首页独立推广入口尚未获得确认，不按已确认功能开发。富文本、媒体及附件能力可与知识点内容复用，业务管理分别保留。

## 2. 知识点课程

已确认：

- 保持一个知识点只有一篇内容，将现有纯文字说明扩展为图文，可混排视频、音频和讲义；不另建多个知识点课程供学生选择。
- 后台采用所见即所得编辑，支持上传图文、插入视频和音频，并提供讲义下载。
- 后台添加视频、音频和讲义时明确选择“上传”或“外链”，两种方式都支持。上传上限 200M（实现按单文件限制，界面与服务端保持一致）。
- 知识点图文所有人可看，音频、视频播放仅对对应考试的 VIP、SVIP 开放。免费用户看到视频缩略图及“该视频仅支持 VIP 和 SVIP”的提示，不可播放。不能仅靠前端遮罩暴露可直接播放的受保护资源地址。
- 在知识点编辑中增加独立的“是否为知识点课程”开关。开关由编辑人员设置，不通过文字长度、是否存在视频音频等条件自动推断；即使只有 50 个汉字，也可以是课程或普通说明。
- 该标记与内容形式、视频播放权益是不同维度；标记为课程不意味着自动把整篇文字锁定，也不等同于节级精讲课。
- 用户已同意提醒策略：练到知识点并出现错题时，优先推荐该知识点课程；没有对应课程时，再推荐节级精讲课。提醒不强制学习，不计入计划题量。普通知识点说明不得作为知识点课程推荐。

待讨论：知识点讲义下载权限、学习记录的口径。本次用户回答明确了图文与音视频，未明确讲义；下载权限单列，不自动归入图文免费或音视频付费。图文全员可看仅适用于知识点内容，不覆盖小抄的限时 SVIP 规则或节级精讲课的既有权限。

实施注意：已有纯文字知识点不应仅凭长度或现有展示自动标记为课程；历史课程数据迁移需保留内容并核对标记。外链的可播放性及访问控制取决于来源能力，不能承诺对任意公开外链实现保密或阻止转发。

## 3. 消息中心

已确认：主要通知订单状态、学习报告生成、学习计划提醒、考试通知；可以融合现有公告。

待讨论：入口、未读状态、个人消息与全体公告的分类、触发时间、重复提醒和频率、点击后的目标页面。H5 站内消息与关闭网页后的系统推送需区分，本轮不默认增加短信或小程序订阅消息。

建议（未确认）：首页铃铛为主要入口，“我的”保留消息中心入口；每日学习提醒合并为摘要，避免每个任务分别刷屏。个人业务通知与公共公告可统一展示，但收件范围必须分别处理。

## 5. AI 专属复习资料

已确认：

- 核心输入是用户自己写的笔记，并结合该笔记对应的题目、知识点和精讲课分析。
- 生成一篇用户个人专属复习资料，不以泛化备考文章代替。
- 资料可能图文并茂，排版和视觉效果要好看，支持生成 PDF 保存。
- 这是重要的增值服务亮点，需在关键位置提供突出的入口。

待讨论：入口位置、用户选择哪些笔记、按单篇/多篇/科目组织、会员权益、生成次数与费用、内容编辑和重新生成、资料保存与 PDF 样式。插图来源以及是否使用图像模型尚未确定。首版可基于笔记及关联内容设计，不必等待 P2 主观题判分。

## 6. 推荐码（本次新规则覆盖旧理解）

已确认：

- 推荐码由后台生成，为 10 位随机字母加数字；替代此前简单的数字推荐码方案。
- 用户注册/登录时可输入，也可登录后在“我的”中输入。
- 记录用户由谁推荐而来。后台记录推荐码关联的前端或后台用户。
- 生成时必须可设置推荐码的使用期限。
- 可以附带 VIP 或 SVIP 体验，体验时长最少 1 小时、最多 72 小时；也可完全不附带体验，仅记录推荐关系。
- 一个推荐码只能绑定一个人。
- 推荐码的可兑换期限与兑换后获得的体验时长是两个独立设置。
- 用户例子：生成后 3 天内有效的码，附带 28 小时 SVIP 体验；用户在有效期内兑换，获得从激活时起计算的 28 小时 SVIP。

待讨论：

- 推荐码的推荐人/归属人、后台生成人、实际使用人如何分别记录；“绑定前后端哪个用户”的准确含义需明确。
- 体验属于哪个考试，以及生成时固定考试还是兑换时选择考试。继承“会员按考试独立”的全局规则，不做全站通用体验。
- 已有 VIP/SVIP 用户兑换后的权益合并规则、体验结束后如何恢复原权益、考试结束与体验期限冲突时如何处理。
- 同一用户可用几个码、已经绑定邀请人时能否再兑码、重复请求处理、码的撤销和重发规则。
- 旧数字推荐码和历史邀请关系的兼容方式。

边界：不自动加入佣金、提现、分销结算；此前这些功能留在后续期次，本次未改变。

2. 知识点课程（与小抄复用编辑及附件能力）。

## 共同约束与沟通方式

- 全站每项权限单独登记，权威清单见 [PERMISSIONS-CATALOG.md](PERMISSIONS-CATALOG.md)。这是用户 2026-09-08 明确新增的基础需求：后台能够配置不同会员所拥有的不同功能权限；不是只有人工切换用户免费/VIP/SVIP。
- 后续各模块设计必须同步更新权限清单，并为可配置权限预留独立标识。管理员操作权限与学生会员权益分开管理；现有硬编码规则需在权限管理开发时迁移，不以清单已建立代表后台已经实现。
- 所有学习业务按考试隔离，共享账号身份；当前考试年度是统一时间配置，不是每个用户购买不同年度。
- 第一版优先 H5，本机 HTTP 测试；不因此次需求登记改变部署方案。
- 未明确的权益、费用、AI 评分标准和业务规则记录为待确认，不擅自补成产品决定。
- 后续每次只围绕选中的模块细化：使用流程、入口、权限、后台管理和验收要求；确认后开发，避免同时展开十个模块。
- 每次实际开发保留 Git 回退点，保持已认可的界面风格。
