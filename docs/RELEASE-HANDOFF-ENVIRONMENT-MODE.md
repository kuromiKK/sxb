# 发布交接：线上内测模式与 H5 存储报错

日期：2026-09-17。目标站点：用户端 `https://h5t.shangxingbao.cn`、后台 `https://htt.shangxingbao.cn`。

发布状态：已于 2026-09-17 完成发布，最终版本 `20260917-env-1789592414023`。服务器 `APP_MODE=production` 保持不变；通过真实后台密码确认切换业务模式为 test，已验证审计、重启持久化、测试验证码与学生协议登录。额外修复 H5 依赖文件名被 Nginx 隐藏文件规则拦截的问题。版本快照、验证与回退记录见 `docs/ONLINE-INTERNAL-TEST.md`。下文保留实现阶段交接要求。

## 用户确认的目标

线上仍是测试环境。后台「系统设置 → 运行环境」可切换测试环境 / 生产环境，顶部标识必须反映真实配置，相关后端行为同时变化。线上测试允许不接短信接口，在登录页面显示测试验证码。

## 已在本地实现

- 新增 `platform_environment` 单行配置表。首次迁移继承服务器 `APP_MODE`；之后以数据库中的选择为准，不会随重启重置，不使用进程内缓存。
- 运行环境选项卡顶部增加环境设置卡片，基本设置不再显示。切换需当前管理员密码、明确确认和修订号校验；仅最高管理员有权限，操作限频并记中文日志。
- 切换时清除旧验证码、未完成的协议登录确认、学生会话；管理员会话和业务数据保留。数据不会自动清空或转换成正式数据。
- 测试环境允许测试短信、模拟支付、符合原条件的测试订单删除。生产环境禁止测试短信、模拟支付、支付宝沙箱支付、模拟 AI 内容和测试订单删除。正式订单在测试环境中也不能模拟支付。
- 生产切换检查服务器安全启动模式、数据库配置、密钥、HTTPS 访问地址、GoCaptcha 配置。短信未开通真实服务时，生产模式的短信登录保持关闭。
- 顶栏、侧栏、运行环境信息、公开配置和健康检查使用同一运行模式。
- 移除首页和学习计划页面自行声明的 `globalThis.uni`，恢复 uni-app 编译器对标准 `uni` API 的处理，修复生产打包后的 `getStorageSync is not a function`。
- 同一工作区还包含之前已完成的管理员删除功能：保护 `18600513966` 和当前管理员，保留历史身份并使会话失效。还有更早的登录验证码、AI 请求修复及部署改动，发布前检查工作区，不要漏掉新增文件。

主要新增文件：`apps/api/src/platform-mode.ts`、`apps/admin/src/PlatformModeSettings.vue`。相关改动分布于 schema、routes、security、site-settings、integrations、订单支付、AI、后台外壳和 H5 页面。请发布完整一致的源码版本，不要只拷贝前端文件。

## 发布方式

1. 在此任务完成后检查 `git status` / diff，把要发布的变更固定为一次可追踪的提交或快照。两个任务若都使用这个目录，文件是共享的；不要一边修改一边读取它打包。不要提交 `.env`、数据库、上传目录或密钥。
2. 沿用 `docs/ONLINE-INTERNAL-TEST.md` 中的既有部署方式。保留线上数据库、上传文件、加密密钥和服务配置；发布前备份数据库，部署新后端与重新构建的后台/H5，不要重新导入本机数据库覆盖线上数据。
3. 保持 `/etc/sxb/app.env` 的 `APP_MODE=production`，它仍控制启动安全与禁止自动导入演示种子数据。**不要为了开启线上测试验证码把它改成 test。** 新的业务模式由后台控制，和服务器安全运行配置分离。
4. 重启 API 自动执行幂等迁移。首次线上迁移会继承旧值 production；在后台「系统设置 → 运行环境」切换为「测试环境」，再确认「接口配置 → 短信」选择「测试验证码」。数据库里已保存 test 短信配置的话，切换后直接生效。若用发布脚本设置模式，使用同等受审计业务流程，不能只修改界面文字。
5. 后端和两个前端一起发布。验收健康检查 `mode=test`、顶栏显示测试环境、学生获取验证码后页面显示测试验证码、协议确认与登录成功、首页不再出现存储 API 错误。

验证码显示在页面不证明手机号归属，使用测试账号，不用于真实学生运营。切换模式不会自动清理测试会员权益或历史内容；正式开放运营前应另行决定哪些测试数据保留或清理。
