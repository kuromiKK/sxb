# 学生端跳转与返回

普通页面打开使用 `openPage` 或 `uni.navigateTo`，返回统一使用 `backOrFallback`。优先恢复原页面栈中的页面（包括筛选、滚动和输入状态），没有原页面时才使用业务兜底页。H5 刷新后，使用本浏览器标签内记录的来源恢复；不根据浏览器历史总长度盲目后退，避免离开网站。

底部五个主菜单使用 `openTab`，已有主页面复用原实例，避免重复点击耗尽小程序页面栈。进入主菜单下的普通功能页仍然保留来源。

登录的来源与登录成功目的地是两件事。取消登录回来源；登录成功回目标，消费登录页，不再次把它压入历史。已在目标页触发登录时，成功后回原实例；目标尚未打开时用目标替换登录。未登录点击“我的”先打开登录，不先进入会反复拦截的个人中心。

`utils/navigation.ts` 的拦截器覆盖旧页面的 uni 导航调用，统一记录完整内部路径及参数。记录仅存当前标签的 sessionStorage，小程序仅存本次运行内存。失败的跳转回滚记录。原生浏览器后退仍由路由器处理。

允许保留的特殊行为：

- 切换考试后重建首页，避免原考试的页面继续使用旧内容。
- 退出账号或换绑后重置栈，避免返回已退出账号的私有页面。
- 下一节课程、下一组练习替换当前内容，返回仍指向该次学习的入口。
- 商品列表打开详情使用独立路由，返回恢复列表；生成结果等非路由的页面内状态仍先关闭当前状态。
- 应用首次加载只允许替换尚未离开的初始页面，不得清空用户已经打开的新页面。

新增页面不直接使用 `window.history.back()`，小程序公共组件不使用 `location.hash`。登录/返回参数只接受站内页面地址。
