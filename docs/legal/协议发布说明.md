# 上行宝协议发布说明（内部使用）

起草日期：2026年9月16日。

本目录包含《上行宝用户服务协议》《上行宝隐私政策》两份完整草案，依据当前项目的商品、订单、学习数据、协议版本和 AI 调用逻辑起草。目标是供运营确认后用于后台“系统设置 → 协议”，本次仅新增文档，未修改默认协议、数据库或已发布版本。

## 一、必须补充的真实信息

- 运营主体全称、有效地址、客服及个人信息保护联系方式、服务时间。
- 实际更新日期、生效日期。草案日期不自动成为对用户生效的日期；正式版本编号由后台发布流程生成。
- 售后首次回复时限和退款办理时限，以及商品如需采用的明确、合理退款细则。草案未擅自设定无理由退款承诺或“一经开通不退”。
- 正式服务器、数据库、文件存储及备份地点；第三方服务商、实际模型接收方、中转方、隐私政策链接及数据流向。不能直接将开发环境或模型名称当作供应商身份。
- 各类数据实际留存、清除及备份覆盖周期。草案中有关15个工作日权利答复、未成年人处理、供应商用途限制等，是拟对外承担的义务，需落实到人员、合同和流程。

## 二、与现有实现相关的发布前事项

| 事项 | 当前核查结果及需要落实的内容 |
| --- | --- |
| 短信、微信登录、真实支付 | 项目文档及代码显示短信与支付主要处于测试模式，微信登录未接入。正式服务商确定后补充清单，不把“微信测试支付”表述为真实微信收款。 |
| 退款 | 已有人工线下退款登记及完成确认，不等于真实资金退款接口。必须确定实际退款人员、渠道、凭证和时限，状态登记需与实际退款一致。 |
| 注销与换绑 | 未见可完成学生账号注销的自助流程；手机号换绑入口提示待短信接入。草案采用人工申请渠道，发布前需落实身份核验、会话失效、数据删除及保留清单，不能仅停用账号。 |
| 数据保存 | 已有历史作答、订单、协议确认、AI 结果等存储；本次未确认自动清理、备份删除任务或全部日志配置。按必要性确定期限后落实执行，不能把“失效”当作“删除”。 |
| AI 数据提供 | 选中笔记会发送至配置的 AI 接口；主观题评分会发送题目、参考答案、评分标准及作答。供应商、接口中转及实际模型链路需逐项核实，并在需要时提供单独同意或出境告知；注册时总勾选不能替代。 |
| 训练与 AI 标识 | 未从代码中证实供应商零训练、零留存承诺，草案也未作此事实保证。需通过服务合同和配置限制用途；同时核对适用的 AI 生成内容标识要求与导出内容标识。 |
| 未成年人 | 当前手机号注册没有已确认的年龄核验或监护人同意机制。落实年龄提示、发现后的处理与儿童注册限制；如决定开放儿童服务，需另行制定规则并建立监护人有效同意机制。 |
| 搜索与权限 | 搜索历史在本地，但关键词仍发往服务器。报告保存图片可能触发相册写入。正式构建需核查宿主平台、第三方 SDK、网络日志和权限，补全清单。 |
| 员工访问 | 后台可查看个人学习记录、笔记、作答、订单及推荐关系。当前主要为最高管理员权限；“职责必需访问”需要人员授权、保密和访问管理配合，不能宣称所有笔记仅本人可见。 |
| 付费履约 | 正式商品按考试、考期发放权益，到期恢复普通用户；已购权益不能因后台手工调整被无依据缩减。文档间存在旧的人工权益规则描述，实际商品承诺与执行应再核对。 |
| 协议变更 | 已有独立版本及确认记录，更新主要在下次登录检查，不主动终止现有会话。若隐私变更要求在新处理开始前重新同意，应在对应处理入口补充控制，不能只等待下次登录。 |

## 三、发布方式

1. 补齐正文中的所有“【待填写】”，完成上表与实际运营的核对。第三方清单删除无关模板行，对尚未启用但保留说明的服务明确标注未启用。
2. 删除两份正文开头的“起草说明”，将版本、日期及联系方式与正式后台配置保持一致。
3. 分别复制到“系统设置 → 协议”的用户服务协议和隐私政策草稿中。保留重要条款的加粗提示，将表格内容整理为编辑器支持的结构。
4. 预览两份全文、联系方式及第三方政策链接，确认登录页和“关于上行宝”入口均可访问，再按已有流程发布新版本，保留原协议历史。
